# ADR 0001：确定性事实不经语言模型工具边界回流

- 状态：已接受
- 日期：2026-07-29

## 背景

年度财务快照和估值比率都是确定性事实。旧数据流先由确定性财务分析 module 生成强类型结果，再把结果序列化为 LLM 工具 JSON，最后由编排层后的 facts module 手写解析、校验并写回 `AnalysisState`。这条路径要求维护另一份 JSON 契约、上下文匹配校验、逐字段类型检查，以及重复、断档和 filing 错年配对等畸形输入测试。

这些校验中的关键不变量已经由取数层构造保证：财年窗口按请求的连续区间生成，filing 直接挂在对应财年的年度记录上。下一步增加季度/TTM 财务层时，如果继续沿用工具回流形状，很容易再复制一套季度工具 JSON 契约、手写校验器和畸形 JSON 测试。

架构文档负责描述当前实现；本 ADR 记录为什么不应把实现改回工具回流路径。

## 决策

写入 `AnalysisState` 的确定性事实由编排层直接向确定性财务分析 module 获取，不使用 LLM 工具返回值作为中转：

- 基本面 facts interface 接收本次 State 的股票代码与财年数，返回年度财务快照和 filing。
- 估值 facts interface 接收股票代码、财年数，以及 LLM 结构化输出声明的价格与市值，返回 PE/PB/PS。
- LLM 的基本面与估值工具继续服务于 Agent 叙事，但工具返回 JSON 不再进入 State。
- LLM schema 与完整 State 模型分开，字段所有权由类型表达；编排层负责把 LLM output 与确定性字段构造成完整 State output。

## 理由

当股票代码、财年数和估值市场输入由编排代码显式传入时，期望上下文不匹配在构造上不可能发生，因此无需再解析工具 JSON 并校验“实际上下文是否等于期望上下文”。

财年窗口的完整性、连续性和唯一性已由 API 层构造保证；filing 与财年的配对已由取数层将 filing 附着到对应 `FinancialRecord` 的方式保证。facts module 应投影这些强类型结果，而不是重复验证同一组不变量。

直接使用 typed interface 还消除了“强类型结果 → JSON → 手写反解析”的往返，使写入 State 的确定性事实只有一条路径，并避免工具输出格式变化波及编排层。

## 后果

正面结果：

- 年度财务事实不受单次 LLM 工具调用参数或消息序列形状影响。
- 估值比率与审计附件中的价格、市值由同一组 LLM 声明值构造，读者可以复算。
- facts module 只处理真实存在的 typed 输入与投影失败，不再维护构造上不可能出现的畸形 JSON 分支。

已接受的代价：

- 基本面 Agent 仍可用与本次 State 不同的财年数调用工具，导致叙事窗口与报告表格窗口不一致，且当前没有告警。
- 估值以 LLM 结构化输出声明的市场输入为准；如果声明值与它实际传给估值工具的值不同，叙事可能引用另一组工具比率。

## 后续约束

季度/TTM 财务层应扩展确定性财务分析 module 的 typed interface，并通过现有 facts seam 投影到 State。不得为了让确定性事实回流 State 而新增季度工具 JSON 契约、手写校验器或畸形 JSON 测试。

叙事窗口与表格窗口是否一致、叙事是否与确定性数字矛盾，属于独立的 Agent 质量校验职责，不应重新塞回事实取值路径。
